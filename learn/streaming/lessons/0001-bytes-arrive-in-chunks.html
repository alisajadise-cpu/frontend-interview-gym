Lesson 1 of 6 · Streaming in the browser

Bytes arrive in chunks

Before you can parse an LLM stream, you have to read one. This lesson takes you from response.body to correct text. ~15 minutes.

Your win today Write the reader loop from memory, and decode text that the network has cut in the middle of a character.

Why stream at all?

You already know await response.json(). It waits until the whole body has arrived. An LLM may take 20 seconds to finish an answer, and nobody wants to stare at a spinner that long. So chat apps show words as they're generated.

The tool for that is response.body: a ReadableStream that hands you the body in pieces, as they arrive.[MDN] Each piece is called a chunk.

Reading a stream

You get a reader, then call read() in a loop until it says done:

const response = await fetch('/api/chat', { method: 'POST', body });
const reader = response.body.getReader();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;          // the server finished the body
  console.log(value);       // Uint8Array(37) [123, 34, 99, ...]
}

Three facts to hold on to:

  • value is a Uint8Array: raw bytes, not text.[javascript.info]
  • Once you read the body this way, you can't call response.json() as well. A body is read once.[javascript.info]
  • for await (const chunk of response.body) also works.[MDN] The reader version gives you reader.cancel(), which you'll need later to stop a stream early.

Bytes are not characters

Text travels as UTF-8, and UTF-8 uses a different number of bytes per character:

CharacterExampleBytes
English lettera1
Persian / Arabic letterس2
Euro sign€3
Emoji👋4

The network cuts the body wherever it likes, by byte count. It doesn't know or care where characters start. So a chunk can end halfway through س. Drag the slider and watch the dashed chunk boundaries:

The left side is what most people write first. Each chunk is decoded on its own, so a half character can't be decoded and becomes � (the "replacement character"). Set the chunk size to 1 and almost everything breaks.

The fix: one decoder, stream: true

Create one TextDecoder for the whole stream and pass { stream: true } on every chunk. That flag means "more data will follow".[MDN] The decoder keeps any unfinished character's bytes and completes it when the next chunk arrives.

const decoder = new TextDecoder();          // ONE, outside the loop
let text = '';
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  text += decoder.decode(value, { stream: true });
}
text += decoder.decode();                   // flush: "no more data is coming"

The last decoder.decode(), with no arguments, says the stream is over. If a broken half character is still waiting, it comes out as � instead of disappearing silently.

Interview question: "Why not new TextDecoder().decode(chunk) for each chunk?"

Answer: "Chunks are cut at byte positions, not character boundaries. A multi-byte UTF-8 character like Persian text or an emoji can be split across two chunks. A new decoder per chunk can't see the other half and prints �. One decoder with stream: true buffers the partial bytes until the rest arrives."

Hint 1

You need three things: one decoder created before the loop, the { done, value } loop, and one more decode() call after the loop.

Hint 2 (if a test about a broken last character fails)

Bytes the decoder is still holding only come out when you call decoder.decode() with no arguments at the end.
